Breakdown 2026-05-29: Codebase inspection confirms net-new files — `src/pages/AgentWorkspacePage.tsx` and `src/components/agents/RunList.tsx` do not exist. The required API surface (`listActiveAgents`, `listAdminActiveAgents`, `listMemorySessions`) is fully live in `frontend/src/lib/api/common.ts`, and the `AgentAuditLogs` component already encodes the session-list + status-icon pattern the spec targets, so implementation code path is clear. Points: 2sp (2 new files, bounded scope, clear layout diagram and exit criteria).

Dependency audit: (1) "0.1 Shell Layout Component" — no standalone kanban task exists; the existing `AgentsPage.tsx` at `/agents` provides a usable shell, making this a non-blocker in practice. (2) "P1B (agent runtime for run data)" maps to `knoxx-tenant-org-scope-runs-memory` (status: incoming) — this task enforces org-scoping on `/api/knoxx/agents/active` and `/api/memory/*`. Without it, `listActiveAgents` and `listMemorySessions` return process-global cross-tenant data, making any RunList component show incorrect results in production and requiring a data-layer revisit post-fix. Same hard blocker that moved `knoxx-1.2-dashboard-agent-runs` to blocked.

Verdict: blocked — implementation is 2sp and technically ready, but cannot be started until `knoxx-tenant-org-scope-runs-memory` reaches done. Once that task ships, the ready gate passes immediately: (a) 2sp, (b) DoD is concrete — `src/pages/AgentWorkspacePage.tsx` mounts at `/agents` (or `/agents/workspace` wired into `App.tsx`), `src/components/agents/RunList.tsx` renders active + recent sections with status icons, all 7 exit criteria from the spec pass in Vitest/manual test: active runs at top, status icons match state, click selects detail, empty state renders, hover shows elapsed time, New Task button visible.
